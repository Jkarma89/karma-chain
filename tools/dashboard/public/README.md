# tools/dashboard/public —— 零构建静态页（功能 003）

由 `../server.mjs` 直接静态托管。**无框架、无打包器、无 CDN、无新增 npm 依赖。**

理由（研究 R-08）：页面的全部交互是"轮询一个 JSON、渲染一张表、按档位换配色、一个按钮"，
框架在这里没有价值；仓库本就没有任何前端构建工具链，引入打包器会新增构建步骤与
产物一致性问题；局域网机器不保证有外网，外部脚本还是一道新的供应链面。

## 前端的三条硬性约束

| 约束 | 为什么 |
|---|---|
| **不做判定** | 档位、百分比、两个余量、异常分类全部取自快照。前端只渲染 |
| **不直连节点** | 只访问本服务的四个路径。判据必须复用服务端的既有实现（FR-004） |
| **不持有密钥** | 探活经 `POST /api/probe`，私钥不出服务端 |

## 文件分工

| 文件 | 归属 | 职责 |
|---|---|---|
| `index.html` | — | 骨架与各视图的挂载点 |
| `style.css` | — | 档位配色与显目性 |
| `copy.mjs` | — | **纯模块**：全部档位/状态文案。零 import，Node 与浏览器共用 |
| `app.mjs` | — | **只做三件事**：轮询、按 `?view=` 路由、装配 DOM |
| `view-health.mjs` | US1 | 百分比、档位、两个余量、新鲜度、探活按钮 |
| `view-nodes.mjs` | US2 | 节点表、Primary 分组 |
| `view-observer.mjs` | US3 | 本机视角不可达、失去观测能力、说法不一致、启动中 |
| `view-domains.mjs` | US4 | 故障边界视图、两个余量的成因、异常四类 |
| `view-identity.mjs` | US5 | 链身份、分叉警报 |
| `view-public.mjs` | US6 | `?view=public` 精简渲染 |

### 为什么按视图分文件

原先的任务清单让 14 条任务横跨全部六个用户故事去改同一个 `app.mjs` —— 与"同一文件的
任务必须串行"直接冲突，六个故事根本无法并行。拆开之后每个故事只碰自己那一个模块。

**任何具体视图的渲染都不许写进 `app.mjs`**，否则会回到抢同一个文件的老路。

### 为什么文案要单独成一个纯模块

FR-008 / FR-020 / SC-006 的判据本质是**"文案里不得出现某些话"**：

- `zero-margin` 必须说"链仍在正常出块"，**不得**出现"链已停止"
- `observer-blind` 全程**不得**出现"链已停止"
- `stopped` **不得**写"数据可能丢失""需要重置"（002 已证明恢复不需要重置）

这类要求**不会自己报错**。把文案埋在渲染函数里就测不到，于是只剩一个"不会变红的守卫"。
抽成零依赖纯模块后，`tests/unit/dashboard-copy.test.mjs` 才能逐档位断言必含与禁止短语。

## 显目性不得只依赖颜色（FR-009）

`stopped` 与 `zero-margin` 必须同时具备**文案差异、版式差异、图形符号差异**三个通道。
色觉差异、投屏偏色、黑白截图这三种常见情形都会让纯颜色编码失效。
