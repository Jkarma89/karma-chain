| 议题 | 为何重要 | 相关 |
|---|---|---|
| **Gas 与费率参数的安全评估** | 无许可链上费率是抗滥用的**唯一**机制；当前值为 Subnet-EVM 默认，未针对开放网络分析过。**且上线后基本改不动**：`upgrade.json` 不能改 feeConfig，唯一的运行时途径 `feeManagerConfig` 预编译已被 ADR-0005 否决，剩下只有"重新部署整条链"。等于主网上线时的取值近乎永久 | ADR-0005 影响节。**主网上线的硬前置**，开发网阶段不必动 |
| ~~**验证者模型的去中心化路径**~~ | **已由功能 002 处理，2026-09-09 完成**：验证者从"单容器内 5 个进程"变为**实际分布在 5 台独立物理机上**的崩溃自愈独立节点，编排工具退出运行时。任一边界整体失效时链继续出块（30 分钟窗口 30/30 笔确认）。**注意这解决的是物理冗余与可恢复性，不是权限去中心化** —— 验证者集合仍由 PoA 合约的单一 owner 管理，那部分留在"主网代币经济学"与未来的治理规格里 | ADR-0004、[0007](0007-failure-domain-independence.md)、[0008](0008-runtime-without-orchestration-cli.md) |
| **主网代币经济学** | 初始分配、是否可增发（当前不可）、手续费处理（当前销毁）需独立规格 | ADR-0003、ADR-0005 |
| **Chain ID 注册** | 20188/20189 已核实未占用，但正式发布前需向 ethereum-lists/chains 提交注册 | ADR-0003 |
| ~~**面向第三方的公开接入信息**~~ | **已完成**（2026-09-03）：`docs/public/chain-info.json` + `developer-quickstart.md`，由 `protocol.json` 生成、有漂移测试，且每一项都可用公开 RPC 独立求证。karma-sc 已改为纯第三方消费者并由测试强制 | 见 `tools/protocol/render-chain-info.mjs` |
| **公开可访问的 RPC 端点** | **局域网连接已是现实（2026-09-09 更新）**：跨机形态下 5 台机器各跑一份 nginx 代理，`http://<机器局域网地址>:8545/ext/bc/karmachain/rpc` 均可用（实测五台应答一致、20–60ms），且代理已把 Host 头统一改写为 `localhost` —— 本条原先提到的 `--http-allowed-hosts` 障碍**在代理路径上已解决**，客户端用主机名或 IP 都可以。代理的上游是**全部 5 个验证者**并配了快速故障转移，因此局域网客户端拿到的是有冗余的入口，不是单个节点。<br><br>**但这些地址刻意不进公开制品**，且由 `tests/unit/public-artifacts.test.mjs` 强制（`publishedHosts` 不得含私网地址）：局域网地址只在某个网段内成立，提交进来会让不同开发者的产物不一致 —— 属消费者侧覆盖的范畴。`chain-info.json` 因此仍只公布回环地址，并在 `rpc.reachability` 里明说"只在跑链的那台机器上有效，其余情况向链的运维方索取地址"。<br><br>**仍未解决的是"公网"那一段**：公网可达性（NAT／端口转发或反向代理）、域名与 TLS、限流与滥用防护，以及**该不该把开发网暴露到公网**这一安全判断本身 | 一有**外部**协作者即需要（局域网内协作现在已经够用）；主网必需 |
| **官方合约 ABI 的发布** | `chain-info.json` 的 `contracts` 目前只有地址、**没有 ABI**。第三方要与官方合约交互，光有地址不够。有业务合约后需把 ABI（或其获取方式）纳入公开接口，并同样做成生成物以防漂移 | 第一个业务合约上链时 |
| **区块浏览器** | 第三方看不到交易、无法验证合约源码、排查失败只能靠 RPC。开放生态下它还是防诈骗的关键一环（源码验证、诈骗标记，见 ADR-0005 下游要求） | 主网前基本必需 |
| **合约升级策略** | 官方合约是否使用代理模式，须在编写合约前决定（宪法第六条） | 智能合约功能 |
