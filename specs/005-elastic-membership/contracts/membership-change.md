# 契约：成员变更（范围 B / C / D）

**规格**：[../spec.md](../spec.md) ｜ **决策**：[../research.md](../research.md) R-03 / R-04 / R-05 / R-06 / R-07 / R-08

## 1. 这份契约保证什么

> **加一个节点、退一个节点，链不重置、既有节点不重启、链上状态不丢。**
> 而且**退之前先把代价说清。**

## 2. 事实来源

| | 在哪 | 谁是权威 |
|---|---|---|
| **实际成员** | 链上（PoA 合约 / P 链） | ✅ **事实来源** |
| **期望成员** | 部署描述 | 声明，不是事实 |

两者不一致 **MUST 可见**（FR-030），三种漂移各有不同处置 ——
见 [../data-model.md](../data-model.md) 第 2 节。

> 文件回答不了「现在有几个验证者」，它只能回答「我们打算有几个」。
> 下一个人会拿 `validators.count` 当答案 —— 所以这一条要写在最显眼处。

## 3. 一次变更的四个阶段

```
前置检查  →  代价告知  →  执行（多步）  →  收尾
```

### 3.1 前置检查（任一不过就拦下，不动链）

| 检查 | 拦下的理由 | FR |
|---|---|---|
| 新节点的创世哈希与基准一致 | 它跑在另一条链上 | FR-014 |
| 目标故障边界的验证者数不超过 f | T-5 越界 —— 加完才在面板上看到边界余量归零就晚了 | FR-013 |
| 恢复能力可用（P 链权益够新节点引导） | 不够的话新节点根本引导不了，人会白等 5 分钟（004 的 V-08） | FR-015 |
| 当前链的健康状态 | 已经零余量时再动成员，风险完全不同 | — |

### 3.2 代价告知（**退出必做**）

```
n: 8 → 7
可离线数: 2 → 1        ← f 下降，要求显式确认
```

**这是整条判据里最反直觉的一格。** 名册少一个看着无关紧要，
而 8 → 7 把容错砍半；事后从面板上只看得到"余量少了"，看不到"是刚才那一步造成的"。

会让链**跌破查询门槛**的退出：拦下，或要求比普通确认更强的确认（FR-012）。

### 3.3 执行（ACP-77，多步跨系统）

```
ValidatorManager 合约调用（L1）
        ↓ Warp 消息
P 链 RegisterL1ValidatorTx / SetL1ValidatorWeightTx
        ↓
ValidatorManager 确认（L1）
```

**判据不是"不会失败"，是"失败时能说出停在哪一步"**（FR-016 / V-10）。
中间失败会在链上留下**半注册状态** —— 工具必须能报出它并支持重试。

### 3.4 收尾

更新期望成员声明；核对链上实际成员；面板在下一个轮询周期反映新状态。

## 4. 两条退出路径

| | 优雅退出 | 紧急摘除 |
|---|---|---|
| 前提 | 机器还活着、能配合 | 机器已损坏 / 失联 |
| 顺序 | **先从集合移除 → 等确认 → 再停进程** | 直接从集合移除 |
| 文档 | 分开写，说明代价差别（FR-018） | — |

**顺序不能反。** 先停进程再移除 = 制造一段"集合里有个死节点"的窗口，
容错余量在那段时间里被白白吃掉。

## 5. 呈现侧必须跟着动（范围 D）

- **门槛与两个余量对任意 n 正确** —— 与 `f(n)` 表逐行一致（FR-024 / V-17）
- **刚加入、仍在引导的验证者不计入参与共识** —— 沿用 003 的 `participatesInConsensus`；
  名册变长**不得**让健康百分比虚高（FR-026 / FR-027 / V-07）
- **明确告知这次变化有没有改变容错** —— n=5→6→7 时 f 都是 1，
  **不得**用"节点更多了"暗示更抗（FR-025）
- **被主动移除的节点不是故障节点**（FR-028）—— 两者处置完全不同
- **T-5 越界显目报出**，不静默通过（FR-029）

## 6. Primary 侧（范围 C）：先拿数，再动手

**不预选方案**（FR-020）。两条候选与要测的四个数见 [../research.md](../research.md) R-07。

**在拿到那四个数之前不写任何实现。**

实施后的判据（FR-022 / V-16）：掉任意 1 个 P 链权益持有者时，
一个被重启的 L1 验证者 **仍能**完成引导并重新加入（≤120 秒）。

004 那个写死的门槛常量 **MUST** 改为按实际权益分布判定，
并保留原注释的意图（说明数字来源是**权益门槛**而非"总数"）（FR-023）。

## 7. 「会变红吗」核对表

| 守卫 | 怎么让它变红 | 期望 |
|---|---|---|
| `f(n)` 对 n=4…12 | 把某一格改错（比如 n=7 写成 2） | 那一格的断言失败 |
| 引导中不计入参与共识 | 让它计入 | 健康百分比虚高，断言失败 |
| 退出前告知 f 变化 | 去掉告知 | 用例失败 |
| 跌破门槛的退出被拦下 | 去掉拦截 | 用例失败 |
| T-5 越界被拦下 | 去掉检查 | 用例失败 |
| 创世不一致的节点进不来 | 去掉核对 | 用例失败 |
| 主动移除 ≠ 故障节点 | 让它产生故障类异常 | 用例失败 |
| 多步失败可报出停在哪一步 | 让它只报"失败了" | 用例失败 |
| 成员漂移可见 | 让声明与链上不一致而面板不报 | 用例失败 |
