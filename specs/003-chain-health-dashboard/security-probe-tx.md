# 安全分析：探活交易的密钥使用路径（功能 003 / T032a）

**为什么有这份文件**：宪法第四条明文要求「任何涉及 **Key Management** 的修改，都必须进行安全分析」，并特别写着「不能因为'只是改几行代码'就跳过安全审查」。

003 **不新增任何密钥**，但**新增了一条密钥使用路径** —— 面板服务读取开发账户私钥并签名交易（FR-034）。`/speckit-analyze`（2026-09-10）把"缺这份分析"判为本特性唯一的 CRITICAL：plan.md 第四条那一行原先只写了"不新增任何密钥"，回避了"新增使用路径"这件事。

**结论**：在既有的本地开发网边界内，该路径可接受。四项条件全部满足，四个泄漏面全部封堵，并各有会变红的守卫。以下逐项。

---

## 1. 涉及的密钥与它为什么被允许存在

| 项 | 值 |
|---|---|
| 来源文件 | `blockchain/accounts/dev-accounts.json` |
| 使用的账户 | `anvil-0`（出资）→ `anvil-1`（收款） |
| 密钥性质 | **生态公开的 Foundry Anvil 默认测试密钥**，全世界都知道 |
| 用途 | 签一笔 0.001 KARMA 的转账，验证链确实能出块 |

宪法第四条 v1.1.0 例外的四项条件逐条核对：

| 条件 | 是否满足 | 依据 |
|---|---|---|
| ① 密钥本身公开已知，或仅在本地开发网络（独立 Chain ID / Network ID）中有效 | ✅ | Anvil 默认账户，公开；且 KarmaChain 开发网是独立的 Chain ID 20189 / Network ID 1337 |
| ② 所在文件与目录带显著 `DEVELOPMENT ONLY` 标记 | ✅ | `dev-accounts.json` 顶层有 `warning` 字段；002 的 no-hardcode 测试把该文件登记为"DEVELOPMENT ONLY 密钥文件的警示文案" |
| ③ 自动化秘密扫描将其列入显式白名单 | ✅ | `tests/e2e/secret-scan.test.mjs` 的白名单；003 未改动该白名单 |
| ④ 生产与 Staging 在技术上不可能接受这些密钥 | ✅ | 不同的 Genesis、不同的 Chain ID、不同的验证者集合。这些密钥在主网上签出的交易不可能被接受 |

**003 没有扩大这个例外的范围**：没有新增密钥、没有新增白名单条目、没有把密钥挪到新位置。变化只是"多了一个读它的地方"。

## 2. 四个泄漏面与各自的封堵

面板是一个 **HTTP 服务 + 网页**，比命令行工具多出几条密钥可能溢出的通道。逐个列出。

### 2.1 HTTP 响应体

**风险**：`POST /api/probe` 的响应若直接回传 viem 的错误对象，可能带出请求体（含已签名的原始交易），甚至在某些库版本里带出账户配置。

**封堵**：响应结构是**固定的五个字段** —— `{ confirmed, blockNumber, elapsedMs, txHash, error }`，逐个由代码构造，从不 spread 任何 viem 对象。`error` 经 `redact()` 处理。

**守卫**：`tests/integration/dashboard-probe.test.mjs` 读取 `dev-accounts.json` 的全部私钥，断言它们（含去掉 `0x` 前缀的形式）**不出现在**响应体文本里。这不是"看代码没问题"，而是拿真实密钥去对照真实输出。

### 2.2 服务端日志

**风险**：把异常直接 `console.error(err)` 会把整个错误对象（可能含请求体）写进日志，而日志会被 `docker logs` 取走、被贴到 issue 里。

**封堵**：`probe-tx.mjs` 不打日志；`server.mjs` 的轮询错误只写 `err.message`，且探活路径不经过那条分支。所有对外文本走 `redact()`。

**守卫**：`redact()` 有单元断言 —— 长十六进制串（≥64 字符）被替换为 `0x…<已隐去>`，且文本截断到 400 字符（不把整个请求体渲染出去）。

> **一处刻意的取舍**：`redact` 会连交易哈希一起抹掉（它也是 66 字符的十六进制）。交易哈希本身是公开信息，抹掉它损失了一点排障便利 —— 但换来的是"面板上永不出现来源不明的长十六进制串"这条简单规则。哈希另由 `txHash` 字段单独返回，信息并未丢失。

### 2.3 快照与公开投影

**风险**：快照是给页面消费的，公开投影更是"可以给第三方看"的。任何密钥落进去都是直接泄漏。

**封堵**：密钥**只活在 `probe-tx.mjs` 的闭包里**，从不进入 `Snapshot`。公开投影（US6 / T065）另有**显式字段白名单**，方向是"挑出允许的"而非"删掉不允许的"。

**守卫**：`dashboard-probe.test.mjs` 断言快照文本不含私钥；`dashboard-public-view.test.mjs`（US6）的三层守卫含一个**行为探针** —— 喂一个刻意含敏感值的假快照，断言那些值不出现在输出里。

### 2.4 前端

**风险**：若前端自己签名，密钥就必须下发到浏览器 —— 那等于把它放进任何能打开页面的人手里，还会进浏览器缓存与开发者工具。

**封堵**：**前端不持有密钥。** 探活经 `POST /api/probe`，签名只在服务端。这也是研究 R-01 选择"服务端采集"的一个附带好处（当时的主要理由是判据复用）。

**守卫**：`tests/e2e/dashboard-readonly.test.mjs` 静态断言 `poll.mjs` 与 `server.mjs` 里不出现 `createWalletClient` / `privateKeyToAccount` / `sendTransaction` —— 钱包接口只能出现在 `probe-tx.mjs`。`tools/dashboard/public/` 下没有任何模块 import viem。

## 3. 失败路径是否会带出密钥

| 失败路径 | 行为 | 是否带出密钥 |
|---|---|---|
| RPC 不可达 | `fetch` 抛错 → `catch` → `redact(err.shortMessage ?? err.message)` | 否 |
| 交易被拒（余额不足 / nonce 冲突） | 同上 | 否 |
| 回执超时（30 秒） | viem 抛 `WaitForTransactionReceiptTimeoutError` → 同上 | 否 |
| 签名本身失败（密钥格式错） | 在 `makeClients()` 内抛 → 同上 | 错误文本可能含"invalid private key"字样，但**不含密钥值**；且长十六进制会被 redact |
| 链处于 `stopped` 档 | 回执超时 → `confirmed: false` + 超时原因，**不是** HTTP 错误 | 否 |
| `dev-accounts.json` 缺失 | `readJson` 抛 → `catch` → 可读的错误 | 否 |

**没有任何路径把私钥值放进返回值或日志。** 最坏情况是错误文本里出现一段被 redact 过的十六进制。

## 4. 「无鉴权 + 一个会写链的端点」这个组合

这两件事单独看都已在规格里登记，但**组合起来**才是真正要评估的东西 —— 分开写会漏掉。

**面板无鉴权**（plan.md Complexity Tracking 已登记）：局域网自用，访问控制由网络边界承担。理由是引入鉴权就要管理凭据，而仓库不得存放真实凭据（宪法第四条）。

**于是**：任何能访问 `localhost:21680` 的人，都能触发一笔 0.001 KARMA 的转账。

风险边界逐条：

| 问题 | 评估 |
|---|---|
| 谁能访问？ | 面板监听在容器内 `0.0.0.0`，但由 `docker run -p 21680:21680` 发布 —— 默认发布到宿主的所有接口，因此**局域网内任何机器都能访问** |
| 最坏能做什么？ | 反复触发转账。单飞守卫保证同时只有一笔在飞，因此速率上限约为"每笔确认耗时"的倒数（实测约 1 秒/笔） |
| 资金后果 | 开发账户 anvil-0 初始 1,000,000 KARMA，每笔 0.001。耗尽需约 10 亿次调用 —— 现实中不构成资源耗尽 |
| 真正的后果 | **污染"高度"这一诊断信号**。持续探活会让高度不断增长，从而毁掉 FR-015（高度停滞不是活性信号）与 `dashboard-idle` 那个用例的前提 |
| 是否泄漏 | 不泄漏。探活不返回任何内部事实；面板的完整快照本就是给局域网内部看的 |
| 生产环境 | **不适用**：面板不做公网暴露（规格范围外条目已排除），且生产不可能接受这些密钥（例外条件④） |

**结论**：这个组合在"局域网自用的开发网"边界内可接受，最坏后果是一个可观测性信号被污染，而不是资金或数据的损失。

**若日后要把面板暴露到公网**（ADR 里"公开可访问的 RPC 端点"仍是未解决的开放决策），则这一节必须重做，且至少要：把 `/api/probe` 与只读端点分开鉴权、或干脆在公网形态下禁用探活。**这一条写在这里，以免那一天有人只看到"面板已经在跑"就直接开端口。**
